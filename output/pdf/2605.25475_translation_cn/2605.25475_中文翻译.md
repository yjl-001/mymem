# IndexMem：用于长上下文 LLM 推理的带 Latent Memory 的可学习 KV-Cache 驱逐

Xintong Yang、Hao Gu、Binxing Xu、Lujun Li、Bei Liu、Jiacheng Liu、Qiyuan Zhu、Sirui Han、Yike Guo

## 摘要

大语言模型（LLM）越来越需要在长上下文上运行，但标准 softmax attention 的 KV cache 会随序列长度线性增长，很快成为长上下文推理的主要瓶颈。一个实际补救办法是驱逐不那么重要的 KV 项；然而，现有驱逐策略大多是启发式的，难以捕捉 token 重要性丰富且依赖输入的分布。

本文提出一个可学习 indexer，用于预测 KV 重要性，从而更准确地保留关键 token。同时，简单地永久驱逐 token 会丢弃其信息，造成不可逆遗忘，并削弱长距离检索能力。为此，作者提出一个轻量 latent memory 模块，把被驱逐 token 压缩进一个紧凑、在线更新的状态，并提供 residual readout，用于补偿 KV 驱逐损失掉的 attention 贡献。

整体方法让模型在有界 KV budget 下仍能进行准确的长上下文推理：在 Qwen、Mistral、Llama 上的 RULER 4K/16K 中都有稳定提升，在激进驱逐下最高提升约 25 分；Needle-in-a-Haystack 检索更稳定；LongBench 分数和压缩曲线也优于已有驱逐策略。

## 1. 引言

LLM 在长上下文理解方面表现出很强能力，支撑了数学推理、代码任务以及制作幻灯片等 agentic workflow。这些应用常常需要处理大规模多模态输入。Gemini3 等模型已经支持百万 token 级上下文，这种规模在视频流或大型代码库输入中并不罕见。

但自回归生成面临关键资源瓶颈。为了避免每个 decoding step 重新计算完整 attention 的二次复杂度，现代推理引擎会使用 Key-Value cache，保存此前 token 的中间状态。KV caching 降低了计算开销，却把瓶颈从计算转移到了显存：KV cache 的占用会同时随序列长度和 batch size 线性增长。例如，在 70B 模型中维护 100 万 token 上下文的 KV cache 约需 320GB GPU 显存，远超多数通用加速卡容量。

这种 memory wall 不仅限制可部署的最大上下文长度，也会加剧 decoding latency，因为巨大的 KV 数据移动会占满显存带宽。已有 KV cache 压缩方法，如量化和低秩近似，主要降低每个 token 的存储成本，但并不解决 cache 随上下文长度线性增长的问题。因此，本文关注 KV eviction：只保留最有价值的 token，从而直接限制显存。

KV eviction 有两个挑战。第一，需要准确预测哪些 token 对未来 decoding 仍然重要。多数现有策略无需训练，依赖静态统计、人工 proxy score 或强建模假设，难以捕捉未来 token 使用中的上下文依赖模式。例如 SnapKV 用局部 attention window 估计重要性，可能偏向近邻 token；KeyDiff 用 key 之间的不相似性作为信息量 proxy；Expected Attention 用语料级 query 统计构造“平均 query”，可能无法适配推理时的具体上下文和 query 分布。

第二，现有方法通常永久丢弃被驱逐 token。如果这些 token 后续重新相关，就无法取回，造成不可逆信息损失。为解决这两个问题，本文提出一个更准确估计 token 重要性的可学习 indexer，并配套一个专门的 memory module，把被驱逐 token 的信息保存下来，供后续检索式补偿。

本文贡献如下：

1. 提出可学习 indexer，更准确地预测 KV token 重要性，实现自适应 KV eviction。
2. 为缓解永久丢弃 token 带来的不可逆遗忘，引入 memory module，将被驱逐 token 压缩进固定大小的 compact latent memory，并在推理中在线更新。
3. 通过大量实验表明，该方法在长上下文性能上持续优于 baseline：RULER 上跨 Qwen/Mistral/Llama 最高提升约 25 分，NIAH 检索更稳健，LongBench 得分更好。

## 2. 背景

### 2.1 Attention 与 KV Caching

Transformer 是现代 LLM 的基础结构。给定输入序列：

$$
X=(x_1,x_2,\dots,x_T)\in \mathbb{R}^{T\times d_{model}},
$$

每个 Transformer block 依次应用 causal self-attention 和 FFN，得到：

$$
X' = f(X)=\mathrm{FFN}(\mathrm{Attention}(X)).
$$

给定 hidden states $X$，self-attention 使用投影矩阵 $W_q,W_k,W_v$ 生成 query、key、value：

$$
Q=XW_q,\quad K=XW_k,\quad V=XW_v.
$$

attention output 为：

$$
O_{attn}=\mathrm{Softmax}\left(\frac{QK^\top}{\sqrt{d_{model}}}+\mathrm{Mask}\right)V=AV,
$$

其中 $O_{attn}\in \mathbb{R}^{T\times d_{model}}$，$A\in \mathbb{R}^{T\times T}$ 是 attention matrix，$\mathrm{Mask}$ 是 causal mask，用 $-\infty$ 屏蔽未来 token。

在自回归 decoding 中，处理新 token $x_{T+1}$ 时重新计算所有历史 token 的 key/value 很低效。KV cache 通过维护历史特征：

$$
C=\{(k_j,v_j)\}_{j=1}^{T}
$$

避免重复计算。对新 token，只需生成 $(q_{T+1},k_{T+1},v_{T+1})$，然后用 query 对更新后的 cache 做 attention：

$$
o^{attn}_{T+1}=
\sum_{j=1}^{T+1}
\mathrm{softmax}\left(\frac{q_{T+1}K_{1:T+1}^{\top}}{\sqrt{d_{model}}}\right)_j v_j.
$$

这说明输出是 cached values 的加权和。KV cache 降低了 decoding latency，但 cache $C$ 随上下文长度线性增长，因而成为长上下文推理的主要显存消费者。

### 2.2 KV Cache Eviction 的统一形式

多数 KV cache eviction 方法都可以统一成“打分 + 选择”框架。给定 cached keys 与 values：

$$
K,V\in \mathbb{R}^{B\times H_{kv}\times L\times d_{head}},
$$

eviction policy 先为每个 cached token position 分配重要性分数：

$$
S=f(\cdot)\in \mathbb{R}^{B\times H_{kv}\times L},
$$

其中 $S_{b,h,t}$ 表示样本 $b$ 中 head $h$ 的 token $t$ 的重要性。随后保留 top-$L'$ token，并沿 sequence 维度 gather 得到压缩 cache：

$$
I=\mathrm{TopK}(S,L'),\quad [K',V']=\mathrm{Gather}(K,V,I).
$$

不同方法主要区别在 score function $f(\cdot)$。SnapKV 用最近窗口 query 对 past key 的 attention mass 作为重要性：

$$
S_t=\frac{1}{w}\sum_{i=L-w}^{L-1}
\mathrm{softmax}\left(\frac{QK^\top}{\sqrt{d}}\right)_{i,t}.
$$

Knorm 用 key magnitude 打分：

$$
S_t=\lVert K_t\rVert_2.
$$

因此，key norm 较小的 token 被认为更不重要，会优先驱逐。TOVA、KeyDiff、Expected Attention 等也可以通过指定各自的 $S=f(\cdot)$ 接入这一统一框架。

## 3. 方法

### 3.1 用于 Token 重要性的可学习 Indexer

KV eviction 的核心难题是通过 proxy 准确估计 token 重要性。现有方法受限于启发式设计，并倾向于过度强调局部 token。受 DeepSeek Sparse Attention 中 lightning indexer 的启发，作者引入一个轻量、可学习 indexer 来评估 KV retention 所需的 token 重要性。

图 1. IndexMem 的整体流程：在主 attention stream 中，可学习 indexer 精确选择需要保存的 KV token，并驱逐其余 token。被驱逐 token 随后在线更新 latent memory；memory readout 作为 residual 加到主 attention stream 上，用来补偿驱逐造成的信息损失。

图 2. Indexer 与 Memory module 的结构。左侧：Indexer 采用 MQA 风格设计，对 multi-head query $q$ 和 single-head cached key $k$ 做 norm，并通过 gated $q,k$ similarity 计算 token score，之后用 max 聚合。右侧：Memory module 从固定大小 latent state 中生成 residual readout $m(q)$；被驱逐 token 在线更新 fast weights $(M,b)$，而 $g(\cdot)$ 与 $\mathrm{Linear}_{\theta}(\cdot)$ 是训练得到的 slow weights。

给定 hidden states $X\in \mathbb{R}^{L\times d_{model}}$ 与 pre-RoPE query states $Q\in \mathbb{R}^{H\times L\times d_{head}}$，indexer 输出 dense query-to-key score matrix：

$$
A=\mathrm{Indexer}(X,Q)\in \mathbb{R}^{L\times L},
$$

其中 $A_{s,t}$ 衡量 key token $t$ 对 query position $s$ 的重要性。

**结构。** 作者先构造 QK-Norm 特征以稳定训练。令 $H_{index}$ 和 $d_{index}$ 分别表示 indexer head 数与每个 head 的维度，通常 $H_{index}\ll H$ 且 $d_{index}\ll d_{head}$，以降低计算。对位置 $s$ 的 multi-head query 做 down-project：

$$
q_s=U_q\mathrm{flatten}(Q_s)\in \mathbb{R}^{H_{index}d_{index}},
$$

再 reshape 成 per-head features $Q_{s,h}\in \mathbb{R}^{d_{index}}$。key 从 hidden states 得到：

$$
k_t=U_kX_t\in \mathbb{R}^{d_{index}}.
$$

沿用 MQA 风格，indexer 对所有 head 使用一个共享 key $k$，并对 $q,k$ 应用 RMSNorm 得到 QK-Norm 特征。

为提升表达能力，作者加入可学习 gate 调节 indexer heads 的贡献。对每个位置 $s$，计算 head-gating vector：

$$
\alpha_s=\frac{GX_s}{\sqrt{H_{index}d_{index}}}\in \mathbb{R}^{H_{index}}.
$$

给定 query position $s$ 与 key position $t$，令 $q_s\in \mathbb{R}^{H_{index}\times d_{index}}$ 是 query features，$k_t\in \mathbb{R}^{d_{index}}$ 是共享 key feature。先计算 per-head similarity $z$，再用 gate 聚合：

$$
z_{s,t}=\mathrm{act}(q_s,k_t),\quad
A_{s,t}=\alpha_s^\top z_{s,t}+\mathrm{Mask}_{s,t}.
$$

然后在 query set $\mathcal{Q}$ 上聚合分数得到 token 级重要性：

$$
\mathrm{imp}_t=\max_{s\in \mathcal{Q}}A_{s,t}.
$$

query set 的定义是：prefill 阶段使用 prompt 中所有 queries；decoding 阶段则在每个 compression interval 内聚合新生成的 queries。

该设计有几个好处。decoding 时，它复用不断增长的 $k$ cache 来预测 token 重要性。不同于 Expected Attention 和 SnapKV 这类通常先 materialize 全量 KV 再驱逐的方法，该 indexer 支持 pre-eviction：在 prefill 前先预测哪些 KV 应保留，使后续 prefill 只计算并缓存被选中的 KV states。

**训练。** 这个 MQA-style indexer 是一个轻量 attention-like 模块，用来预测 backbone attention scores。训练时冻结 backbone LLM，只优化 learnable indexer。给定长度 $L$ 的序列，indexer 输出 score map $A\in \mathbb{R}^{L\times L}$，其中 $A(q,k)$ 是每个 query 对 key 的 logits。

作者用蒸馏让 indexer 匹配 backbone 的 attention 行为。具体地，用 teacher attention logits：

$$
T=\frac{QK^\top}{\sqrt{d_{model}}},
$$

并在 query 维度做 max pooling：只要某个 key 被任一 query 高度关注，它就被认为重要。优化目标为：

$$
D_{KL}\left(
\mathrm{softmax}\left(\max_q T(q,\cdot)\right)
\;\middle\|\;
\mathrm{softmax}\left(\max_q A(q,\cdot)\right)
\right).
$$

为了稳定优化，作者从 KL loss 中排除 sink tokens，因为这些 token 的 attention weight 持续很大，会支配梯度。

直接 materialize 完整 teacher score matrix $T$ 会需要 $O(L^2)$ 存储。作者改用 streaming 的 FlashAttention 风格计算：按 query chunk 和 key chunk 遍历，在线更新 key 维度上的 $O(L)$ running-max vector，从不实例化完整 $L\times L$ attention map。最后在 key 轴上做数值稳定的 softmax，并精确计算 pooled distribution 的 KL。

### 3.2 面向被驱逐 Token 的 Latent Memory

多数 KV cache compression 方法采用 evict-or-keep 决策：token 一旦被驱逐，其 KV states 就被永久丢弃。这对检索式 benchmark 可能够用，因为只需保留少量 evidence token；但对整体长上下文推理，如问答与摘要，有用信息可能分散在大量看似低 saliency 的 token 中。激进驱逐会造成随时间积累的不可逆信息损失。

已有缓解遗忘的方法包括 KVReviver 这类基于 reconstruction 的方法，它们从 compact sketches 重建 KV，但容易在 softmax 中放大误差。NOSA、InfLLM 等 offloading 方案把 token 保存在 CPU memory，但 CPU-GPU 数据传输延迟会带来吞吐瓶颈。

IndexMem 把被驱逐 token 压缩进固定大小 latent memory。该 memory 设计包含两个问题：如何把被驱逐信息写入 memory，以及如何读出它来补偿 attention。

**为什么不用 memory-as-tokens。** 直接做法是把被驱逐 KV 写入少量 latent KV tokens，让标准 softmax attention 同时读取 retained tokens 与 latent memory。但 token placement 很棘手：如果把 latent tokens 放在 prefix，它们往往变成 attention sinks，吸走大量 attention mass；如果放在后面，早期 queries 又无法访问。可以用特殊 attention mask 让 latent tokens 对所有 queries 全局可见，但这种形式仍然脆弱：latent tokens 可能坍缩成通用“均值”摘要，softmax 也可能放大小错配。

**用 residual compensation 读 memory。** IndexMem 不把 latent memory 注入 softmax 内部的额外 KV token，而是把 memory 看成被驱逐信息的显式补偿 residual。具体地，在原始 attention output 上加 gated memory readout：

$$
o=o_{attn}+g(q)\cdot m(q),
$$

其中 $o_{attn}$ 只在保留的 KV cache 上计算。$m(q)$ 是根据当前 query $q$ 从被驱逐 tokens 中读出的有用信号。gate $g(q)\in [0,1]$ 控制当前 query 是否以及多大程度依赖 latent memory；当 $g(q)=0$ 时，模型可以安全退回只用主 attention stream。

**Memory module 中的 slow weights 与 fast weights。** 每层使用一个 latent memory module，在所有 attention heads 间共享。模块由两部分组成：slow weights $\theta$ 由训练梯度更新；fast weights 在推理时按简单规则在线更新。只用 slow weights 往往会坍缩成数据集特定的被驱逐 attention 均值补偿。fast weights 维护固定大小状态矩阵：

$$
M\in \mathbb{R}^{d_{mem}\times d_{model}},\quad
b\in \mathbb{R}^{d_{mem}},
$$

其中 $d_{mem}$ 是 memory-state dimension。给定 query $q\in \mathbb{R}^{d_{model}}$，先计算 $\mathrm{Linear}_{\theta}(q)\in \mathbb{R}^{d_{mem}}$，再从 memory 读取：

$$
m(q)=
\frac{\mathrm{Linear}_{\theta}(q)^\top M}
{\left(\mathrm{Linear}_{\theta}(q)^{\odot 2}\right)^\top b+\epsilon}.
$$

**Online write as fast-weight updates。** memory state $(M,b)$ 在每次 eviction 后在线更新。给定被驱逐集合 $\mathcal{E}$ 及其 key-value pairs $\{(k_i,v_i)\}_{i\in \mathcal{E}}$，用带 decay 的 outer-product accumulation：

$$
M\leftarrow \lambda M+\eta\sum_{i\in \mathcal{E}}\mathrm{Linear}_{\theta}(k_i)v_i^\top,
$$

$$
b\leftarrow \lambda b+\eta\sum_{i\in \mathcal{E}}\mathrm{Linear}_{\theta}(k_i)\odot \mathrm{Linear}_{\theta}(k_i),
$$

其中 $\lambda\in (0,1]$ 是 decay factor，$\eta>0$ 是 write strength。

**Slow-weight training。** 作者用梯度训练 slow-weight components，即 projection $\mathrm{Linear}_{\theta}(\cdot)$ 和 gate $g(\cdot)$，使 memory readout 匹配 eviction 引入的 missing residual。优化 MSE：

$$
\mathcal{L}_{mem}
=\lVert o-o_{attn}-g(q)\cdot m(q)\rVert_2^2,
$$

其中 $o$ 是 full attention output，$o_{attn}$ 是 compressed KV cache 上的输出。

## 4. 实验

### 模型与评估设置

实验使用三个代表性 LLM backbone：Qwen3-8B、Mistral-7B-v0.3、Llama-3.1-8B-Instruct。压缩率定义为 $r\in [0,1]$：每个方法驱逐 $r$ 比例的 cached KV entries，并根据 token-importance scores 保留 top-$(1-r)$ 比例。为避免 sink tokens 导致退化，所有方法额外保留 cache 中前四个 token。

作者在 NVIDIA KVPRESS 框架中实现 IndexMem 和所有 baseline，确保 eviction 协议和比较设置一致。除非特别说明，实验在单张 NVIDIA H800 GPU 上运行。

### 推理计划与 Cache Budget

评估主要针对 long-prefill、short-decode 场景。对长度 $L$ 的 prompt 完成 prefill 后，立即计算 token 重要性，进行 one-shot compression，并把被驱逐 KV pair 写入 latent memory。具体地，将 prefill KV cache 压缩到固定比例 $(1-r)L$，也就是驱逐 $r$ 比例 token。

decoding 阶段，每生成 $\tau=128$ 个 token 做一次 periodic compression，以防 cache 不断增长。每次 compression 用自上一次 compression 以来的所有 queries 给 token 打分，并在固定 KV budget $B_{max}$ 下保留最重要项。实现上，$B_{max}$ 可设为 $(1-r)L$ 加上最近 local window。

### 训练设置

Indexer 使用 $H_{index}=H/4$ 个 heads，其中 $H$ 是 backbone LLM attention head 数。down-projection dimension 设为 $d_{index}=d_{head}/8$。Memory module 中 latent dimension 设为 $d_{mem}=d/8$，其中 $d_{model}=H\cdot d_{head}$。

训练时冻结 backbone LLM，采用两阶段训练：

1. 先单独训练 indexer，让它学习估计 token 重要性并做可靠 eviction。
2. 再联合训练 indexer 与 memory module。latent memory 以 evicted-attention output 为学习信号，学习补偿 eviction 损失的信息。

作者在 LongAlpaca 上做 SFT，使用 chunk-wise KL objective，并采用 DDP 训练。学习率使用 warmup-stable-decay schedule：100 warmup steps 到 $1\times 10^{-3}$，随后 2000 stable steps，再用 2000 decay steps 降至 $7.5\times 10^{-6}$。

### Baselines

比较方法包括 Expected Attention、KeyDiff、TOVA，以及广泛使用的 heuristic compressors SnapKV 和 PyramidKV。所有 baseline 都在同一框架和同一协议下实现与评估。

### 消融

作者做了两类消融。第一，比较 Indexer only 与 IndexMem（Indexer + memory residual）。在 LongBench 任务上，加入 memory 带来稳定收益，且激进压缩下收益最大。尤其在 trec 和 qasper 这类任务上，memory residual 显著减少 Indexer only 在高压缩时的灾难性失败，说明存储被驱逐 token 并读回，对缓解 eviction 带来的不可逆遗忘很关键。

第二，评估 memory module 是否绑定于本文 indexer，还是可泛化到其他 eviction policy。作者把同一个 memory module 接到 SnapKV 上，形成 SnapKV+Memory：SnapKV 选择的被驱逐 token 用来在线更新 memory，memory readout 作为 residual 加回。结果显示 SnapKV+Memory 在多个任务上稳定优于 SnapKV，说明 proposed latent memory 很大程度上与 eviction heuristic 正交，可作为 drop-in component 恢复 KV eviction 丢失的信息。

## 5. 相关工作

**Sparse Attention。** 大量工作通过稀疏化 attention computation 提升长上下文效率：有的施加结构化 pattern，有的动态限制访问哪些 KV block。Quest 进行 query-aware KV page selection；MInference 利用动态 sparse attention 加速 prefilling；MoBA 用 mixture-of-experts 风格路由 block attention；NSA 设计硬件友好且可训练的 sparse attention 机制。

**KV Cache Compression。** KV cache compression 大致分为两类，且通常可正交组合。representation compression 降低每个 token 的 KV footprint，例如 KIVI、ZipCache 等低比特量化。token reduction 则通过 eviction 或 selection policy 只保留 token 子集，直接限制 KV memory。H2O 保留 attention contribution 大的 heavy hitter tokens 并结合 recency；SnapKV 使用 prompt 末端短 observation window 推断 salient KV positions，可能引入 locality bias；KeyDiff 用 key similarity/diversity 作为重要性 proxy；Expected Attention 通过建模未来 query distribution 估计 KV importance；Lookahead Q-cache 则生成 pseudo lookahead queries 以改善 eviction consistency。

**Memory。** 扩展 LLM 有效上下文的一种常见方法是引入 external memory，例如 agentic retrieval 或 RAG-style pipeline，把过去信息存在外部 datastore 中，并在推理时检索相关 chunks。这类方法有效，但依赖额外 retriever，引入系统复杂度，也可能受到检索错误或延迟影响。另一类工作把 memory 整合进模型内部，例如 test-time adaptation 或 fast-weight mechanisms。Titans 维护在线更新的 memory state；Product Key Memory 与 fast-weight variants 提供大容量 associative memory；TTT-E2E 等 test-time training 方法在生成中在线更新紧凑参数或内部状态，以吸收长距离信息。

## 6. 结论与局限

本文提出 IndexMem，一个面向长上下文 LLM 推理的可学习 KV-cache eviction 框架。方法引入可学习 indexer，更准确地预测 KV-token 重要性；同时提出在线更新的 latent memory module，通过 residual readout 补偿主 attention stream 中因 token 驱逐丢失的信息。两个组件一起展示了 learnable architectures 在高效 attention 上的潜力，并在长上下文 benchmark 上实现了更好的 accuracy-memory trade-off。

## Impact Statement

本文目标是提升长上下文 LLM 推理效率。通过降低 KV cache 显存占用，IndexMem 可能降低长上下文模型服务的硬件成本，使有限计算资源下部署这类系统更可行，也可能降低能源与基础设施需求。

同时，推理效率提升也会让 LLM 更容易大规模部署，包括模型输出可能不可靠、有偏或被滥用的场景。此外，KV-cache eviction 与 memory compression 会影响输入中哪些部分被保留，因此在高风险领域使用时需要谨慎：遗漏一个小但关键的细节可能导致有害决策。IndexMem 应被视为通用效率技术，而不是解决更广泛安全与可靠性问题的方法。实践者应在目标用例上仔细评估 compressed long-context systems。

## A. 局限与未来工作

长链式思维（CoT）推理已经成为现代语言模型的标准能力，但更长的 CoT 也会显著增加 KV-cache 显存消耗，并成为长上下文推理中的主要瓶颈。因此，memory-efficient LLM 研究正在从参数压缩和量化，扩展到减少 KV-cache footprint。本文关注的方向与缩短推理长度或自适应控制 CoT generation 互补：在保留长上下文推理能力的同时提升 KV-cache 效率。

当前设计空间仍远未充分探索。第一，用于学习 token importance 与 memory updates 的训练目标和监督信号可能不是最优的，特别是在极端压缩率下，保留少数关键 token 变得很困难。第二，训练在有限 token budget 和相对中等规模 setting 下完成，还没有充分评估大规模训练 regime 或更广泛模型族。第三，当前方法是在冻结 backbone 的前提下作为 add-on module 训练。未来重要方向是让 backbone model 通过 continual training 获得原生 eviction-and-memory 能力，使 efficient attention、eviction decisions、memory writing/reading 可以端到端联合学习。

## B. Cross-layer Score Redundancy 与 Index Reuse

### B.1 动机：跨层冗余

层级 token scores 可能很 noisy，不同层的 token scoring quality 差异很大。有些层给出的 score distribution 判别性弱、接近 uniform，使 top-K selection 对小扰动很敏感。这促使作者聚合多个 layer-wise score signals 来降低方差。

另一个观察是，相邻层的重要 token set 往往部分共享。虽然不同层的 score magnitude 不同，但 top-K retained indices 常常有非平凡重叠，尤其在相邻层之间。这说明不一定需要为每一层都重复计算完全独立的 token-importance signal。可以通过 soft score aggregation 合并跨层 score vector，也可以通过 hard index reuse，在短层组内复用 selected indices 或 indexer scores。

### B.2 Running Mean 作为跨层 Score Aggregation

给定层级 score vector $s_{\ell}\in \mathbb{R}^{T}$，running mean 计算跨层平均 score：

$$
\bar{s}^{(naive)}_m=\frac{1}{m}\sum_{\ell=1}^{m}s_{\ell},
\quad m=1,\dots,N_{layer}.
$$

实际使用 $\bar{s}^{(naive)}_{N_{layer}}$ 做 top-K selection。平均可以在部分层 score noisy 时降低方差，尤其当重要 token set 在相邻层部分共享时有意义。

但朴素平均在 spiky-dependency tasks 上可能失败：如果任务需要保留少数高度关键 token，少数层可能给出尖锐且准确的 score distribution，其他层却很 diffuse。朴素平均会把低质量 diffuse signal 混入尖锐 signal，降低关键 token 与其他 token 的相对 margin。

作者用 normalized entropy 作为 score source 是否有判别性的 proxy：

$$
H(p)=-\frac{1}{\log T}\sum_{t=1}^{T}p_t\log(p_t+\epsilon),
$$

其中 $H(p)\in [0,1]$。高 entropy 表示近似 uniform、判别性弱；低 entropy 表示集中在少量 token 上，具有强偏好。

Entropy-gated running mean 会跳过 entropy 高于阈值的层或 head。令 $H_{\ell}$ 是第 $\ell$ 层的 normalized entropy，阈值 $\gamma\in [0,1]$，定义：

$$
\alpha_{\ell}=\mathbb{I}[H_{\ell}\le \gamma].
$$

则 entropy-gated mean 为：

$$
\bar{s}^{(skip-high)}
=
\frac{\sum_{\ell=1}^{N_{layer}}\alpha_{\ell}s_{\ell}}
{\sum_{\ell=1}^{N_{layer}}\alpha_{\ell}+\delta}.
$$

这是带 quality filter 的方差降低策略：只聚合看起来有选择性的低 entropy 层，避免 under-confident 的高 entropy 层污染 aggregated signal。

表 2. Expected Attention 与 running-mean variants 在不同压缩率下的 RULER 平均分。数值越高越好。

| Method | CR=0.25 | CR=0.50 | CR=0.75 | CR=0.90 |
|---|---:|---:|---:|---:|
| EA | 89.19 | 76.53 | 54.53 | 27.78 |
| Layer-mean RM | 81.43 | 74.00 | 51.98 | 31.93 |
| RM + entropy skip-high | 89.71 | 79.08 | 57.76 | 32.93 |
| RM + entropy skip-low | 82.32 | 73.38 | 54.07 | 33.13 |
| RM + peak gate | 82.44 | 74.94 | 54.66 | 32.36 |
| RM + peak gate, keep-high | 83.27 | 74.84 | 52.79 | 31.02 |

实验显示，用 softmax entropy 做 skip-high 的 entropy-gated running mean 稳定优于 naive layer-mean running mean，并在中等压缩率下常常与 EA 相当或更好。极高压缩率 $CR=0.90$ 时最佳 variant 会变化，说明 retained context 极稀疏时 failure mode 不同。

### B.3 从 Running Mean 到 IndexCache

Running mean 通过平均 score values 利用跨层冗余。但如果相邻层 top-K token set 已经很相似，更简单的实现是复用 score 或 index decision。这就是 IndexCache-style 策略：不是每层都独立重算 indexer scores，而是在一小组相邻层内计算一次 indexer scores，并复用 scores 或 selected indices。作者实现中，每 4 个连续层复用一次 indexer scores。

该复用策略不改变 IndexMem 的核心 token-selection objective，只是利用重要 token set 的经验冗余摊销 score computation overhead。Running mean 可视为 soft aggregation diagnostic，而 IndexCache-style reuse 是同一跨层冗余的轻量实际实现。

表 3. 在 Mistral-7B 上带 IndexCache-style score reuse 的 RULER 结果。数值越高越好。

| Method | 4K-25% | 4K-50% | 4K-90% | 16K-25% | 16K-50% | 16K-90% |
|---|---:|---:|---:|---:|---:|---:|
| IndexMem + IndexCache | 92.4 | 90.0 | 76.1 | 82.5 | 79.3 | 66.8 |
| AdaKV | 72.8 | 56.7 | 22.8 | 68.6 | 52.1 | 23.8 |
| SnapKV | 57.6 | 41.3 | 19.8 | 49.5 | 36.5 | 21.3 |
| TOVA | 78.4 | 75.5 | 29.2 | 73.8 | 70.1 | 47.7 |

这些数字使用 Section 4 的更新训练 recipe（WSD learning-rate schedule）和 IndexCache-style score reuse，因此不能直接与 Table 1 中 Mistral-7B 的 IndexMem 条目比较。结果显示，该 variant 在 4K 和 16K RULER 上都保持强精度，并在相同压缩率下优于 AdaKV、SnapKV、TOVA。

### B.4 Takeaway 与适用范围

Running-mean study 是对跨层 score aggregation 的分析，而不是最终 IndexMem inference algorithm。它说明 layer-wise token-importance signals 中存在可复用信息：聚合 selective layers 可以稳定 token selection，而高 entropy 层可能引入噪声。IndexCache-style reuse 用更简单实用的方式，在相邻层之间复用 indexer scores 或 selected indices，以降低 indexer overhead。

该观察也有限制。Entropy 只是 score reliability 的 proxy：低 entropy 不保证正确，高 entropy 也不必然无用。阈值 $\gamma$ 依赖任务与模型，跳过太多层也可能削弱聚合收益。因此作者把 running mean 视为 diagnostic aggregation study，而使用 IndexCache-style reuse 作为实际轻量 variant。

## D. 符号

令 $T$ 表示序列长度，$B$ 表示 batch size。Transformer hidden size 为 $d_{model}$，attention head 数为 $H$，每个 head 维度为：

$$
d_{head}=\frac{d_{model}}{H}.
$$

对 grouped-query / multi-query attention，令 key/value heads 数为 $H_{kv}$，且 $H_{kv}\le H$。cached keys/values 形状为：

$$
K,V\in \mathbb{R}^{B\times H_{kv}\times L\times d_{head}}.
$$

主文中 token hidden states 记为 $X\in \mathbb{R}^{L\times d_{model}}$，indexer 使用的 pre-RoPE query states 记为：

$$
Q\in \mathbb{R}^{H\times L\times d_{head}}.
$$

indexer 使用 $H_{index}$ 个轻量 heads，每个 head feature dimension 为 $d_{index}$，通常 $H_{index}\ll H$ 且 $d_{index}\ll d_{head}$，输出 dense query-to-key score matrix：

$$
A=\mathrm{Indexer}(X,Q)\in \mathbb{R}^{L\times L}.
$$

latent memory module 在 model space 中运行，维护固定大小 fast-weight state：

$$
M\in \mathbb{R}^{d_{mem}\times d_{model}},\quad b\in \mathbb{R}^{d_{mem}}.
$$

给定 query vector $q\in \mathbb{R}^{d_{model}}$，memory feature map 为：

$$
\phi(q)=\mathrm{Linear}_{\theta}(q)\in \mathbb{R}^{d_{mem}}.
$$

除非另有说明，attention softmax scaling 都使用 $\sqrt{d_{model}}$。

## E. PyTorch 风格伪代码

**Indexer 与 Memory module。**

- 输入：hidden states $X$、pre-RoPE query states $Q$、causal mask、用于聚合的 query set，以及 decoding 中持续增长的 key cache。
- indexer 先 down-project multi-head queries 并做 norm，再用共享 key 构造 MQA-style score。
- gated similarity 得到 score matrix $A$，再对 query set 取 max 得到 token importance。
- latent memory 维护 $M,b$，读操作为 $\mathrm{mem\_read}(q)$，写操作把 evicted keys/values 通过 outer product 累积进 fast weights。
- 最终 residual compensation 为：

$$
o=\mathrm{attn}(q,KV_{kept})+g(q)\cdot \mathrm{mem\_read}(q).
$$

**Streaming KL Distillation Loss。**

训练 indexer 时，目标是：

$$
\mathrm{KL}\left(
\mathrm{softmax}(\max_q T)
\;\middle\|\;
\mathrm{softmax}(\max_q A)
\right).
$$

实现上，算法按 query block 与 key block 流式遍历，分别维护 teacher importance 与 student importance 的 running maximum。causal mask 会屏蔽未来 key，sink mask 会排除 sink token。最后对有效 token 的 pooled teacher/student importance 做 log-softmax，并计算 KL loss。这样可避免 materialize 完整 $L\times L$ teacher attention matrix。
