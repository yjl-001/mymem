## 阅读提示

这篇论文提出的 Latent Memory 与 MemGen 的“推理流中的 latent memory token”很相关，但它的侧重点不同：本文把外部文本或图像证据压缩成单个高维 latent token，用于检索和问答生成；MemGen 更关注 agent 经验在推理过程中的生成式 latent memory 插入。

本文档是中文阅读版：主文按论文结构翻译，关键公式、图题、实验表格和附录结论保留；参考文献保留英文，不逐条翻译。

## 摘要

外部记忆能够有效地把基于大语言模型（LLM）和视觉语言模型（VLM）的问答系统锚定到相关的多模态证据上。然而，现有记忆范式通常以原始文本和图像形式表示每个记忆项，因此基于检索的系统必须把检索到的文本或图像传给生成 LLM/VLM。这会带来很高的 token 消耗和存储压力，使其难以用于资源受限应用。

本文提出 **Latent Memory**，一种 latent-space 记忆范式：它用一个小型 compressor LLM/VLM 为每条原始文本或图像证据生成一个高维 latent token，并用这个 latent token 替代原始证据。Latent Memory 不再为生成阶段检索原始证据，而是在统一 latent 表示空间中工作：查询被嵌入到同一空间以检索相关 latent token，检索出的 latent token 被直接提示给预训练 LLM 或 VLM 来生成答案。

为了让每个 latent token 同时对重建、检索和生成有用，作者使用重建目标、对比目标和蒸馏目标，以统一端到端方式训练 compressor。论文在七个纯文本 QA 和多模态 QA benchmark 上评估 Latent Memory。结果表明，它在相比先进 RAG baseline 达到有竞争力 QA 性能的同时，让生成器 token 消耗减少 3 到 10 倍；在 WebQA 上，它还取得了最强的图像证据问答表现。

## 1 引言

大语言模型和视觉语言模型已经在复杂推理和知识密集型任务中展现出很强能力，尤其是在配备外部记忆并能检索相关记忆项时，可以产生更忠实、更可靠的生成结果。这里的外部记忆通常包含外部知识证据或对话历史，并可能以多模态形式存在。它让模型在长上下文任务或多轮对话中把输出锚定在证据上，因此成为许多应用的核心组件，例如长上下文问答、代码 agent 和 agentic AI 助手。

尽管外部记忆能通过提供相关证据改善答案生成，但主流记忆范式仍然计算代价很高。主要瓶颈在生成阶段：记忆中的证据通常以未压缩形式被提示给 LLM/VLM 生成器，导致大量 token 成本和延迟开销。多模态记忆会进一步放大这个问题，因为每张图像可能需要 MB 级存储，并在生成阶段扩展成数百个视觉 token。上述成本限制了外部记忆在长上下文和多轮交互中的可扩展性，也让它难以部署到存储或延迟预算很紧的环境中，例如端侧助手和 edge-AI 应用。

图 1：现有显式上下文记忆式 QA 与本文 Latent Memory 范式的对比。传统 RAG 保存并传入原始文本/图像证据；Latent Memory 先把每条多模态证据压缩成单个 latent token，再在统一 latent 空间中检索并把 latent token 传给生成器。

为了追求面向严格延迟或存储约束应用的高效记忆表示范式，本文研究一个问题：多模态上下文记忆是否可以被表示为高度压缩的 one-token latent representation，并在生成阶段替代原始证据？

为此，作者提出 Latent Memory。它把每个证据单元压缩成紧凑、可检索的高维 latent token，并且这些 token 可以被 frozen LLM/VLM 生成器直接使用，而不需要微调生成器。如图 1(b) 所示，Latent Memory 使用小型 compression LLM/VLM 把每条文本或图像上下文编码为单个 latent token，形成统一的多模态 latent 表示空间。在查询阶段，问题被嵌入到同一空间中，通过相似度搜索检索相关 latent token。随后，这些 latent token 被投影到 frozen LLM/VLM 的隐藏维度中用于答案生成，从而替代传统 token 级上下文。

该设计带来两点能力：

- **Token 效率与存储效率**：Latent Memory 减少处理多模态上下文证据时的 token 消耗和存储压力。
- **统一表示与检索空间**：同一个 latent token 同时用于上下文表示和检索，使低预算 embedding 更容易学好。

为了获得更好的多模态证据 latent token，作者微调一个小型 LLM/VLM，使生成的 token 同时保存原始信息和检索能力。训练损失包含三部分：

- 重建损失，保证 latent token 携带足够原始证据信息；
- 对比损失，把查询与其标注的支持证据在 latent 空间中对齐；
- 蒸馏损失，把“以 latent token 为提示的生成行为”对齐到“以原始正证据为提示的生成行为”。

在 2WikiMultihopQA 和 MuSiQue 上，使用 HotpotQA 训练的 one-token Latent Memory 相比原始证据 RAG baseline 达到有竞争力的 EM/F1，同时只使用约三分之一的 LLaMA-8B 或 Mistral-7B 生成器 token。在多模态 QA benchmark 上，Latent Memory 在 LLaVA-13B 和 Gemma3-12B 生成器下带来约 10 倍效率收益，并在 image-grounded QA 上取得突出结果。

本文贡献如下：

- 提出 Latent Memory：一种面向资源受限场景的高效多模态记忆范式，把每条证据编译为单个高维 latent token。
- 证明 one-token Latent Memory 可以通过重建、对比学习和蒸馏组合目标，同时支持检索和答案生成。
- 在八个纯文本和多模态上下文 QA benchmark、四个生成 LLM/VLM 上，实证展示 Latent Memory 显著改善效率-性能权衡。

## 2 相关工作

**外部记忆与 RAG。** 在可信 QA 中，LLM/VLM 通常把给定多模态上下文作为记忆，并通过 full-context prompting 或 RAG 与外部记忆交互。Dense Retrieval、BM25 Retrieval 以及近期 RAG 方法会把查询和证据编码到共享空间中进行近邻搜索。在多模态场景中，近期多模态 embedding 方法可以基于 embedding 模型检索图像，并把图像 token 提示给 VLM，例如 LLaVA 中约 576 个视觉 token、Gemma VLM 中约 256 个视觉 token。问题是，这些方法都在原始证据层表示记忆；随着多模态记忆规模扩大，原始证据表示会成为存储和效率瓶颈。Latent Memory 则把多模态证据存成紧凑 latent token，只把 latent vector 注入生成 LLM/VLM，从而降低生成 token 成本。

**证据压缩。** 除 RAG 外，也有一些 Evidence Compression 方法试图处理过长记忆。LLMLingua 学习丢弃不必要 token；AutoCompressor、ICAE 和 LCC 学习把文本文档压缩成少量连续 token，用于高效 LLM QA 生成；xRAG 和同期工作 CLaRa 则把同样的 latent 用于检索。但这些方法主要面向文本场景，难以兼容近期多模态记忆设置。并且，论文在附录 A.2 指出，高维 token 实际上可能比短文本证据单元更大，所以这些算法在多模态设置中不能像 Latent Memory 一样提供图像侧存储节省。

**Latent-space 推理。** Latent reasoning 方法表明，LLM 可以通过连续 latent state 而非离散 token 序列进行推理和通信。也有工作尝试在统一 embedding 空间中表示多模态理解与生成。Latent Memory 将这一原则用于新的记忆范式：多模态证据在统一 latent 表示中被编码、检索并作为提示输入生成器。

## 3 方法：Latent Memory

为了实现高效外部记忆，本文提出 Latent Memory 范式。本节先说明 one-token Latent Memory 如何构建并用于 QA 生成，然后说明如何训练 compression LLM/VLM 来产生这些 latent memory。

### 3.1 定义：用于上下文记忆 QA 的 Latent Memory

一个 QA 问题需要在 $N$ 条外部上下文 $C=\{x_i\}_{i=1}^{N}$ 条件下，回答问题 $Q=(q_1,q_2,\ldots,q_{|Q|})$，答案为 $A=(a_1,a_2,\ldots,a_{|A|})$。把所有上下文 $C$ 都提示给生成器可以改善困惑度，但在某些情况下会超过预训练上下文窗口。因此，RAG 系统一般检索原始证据子集 $R(Q,C)$，再把它们提示给 LLM/VLM 生成器：

$$
P(A \mid Q,C,\phi)=\prod_{t=1}^{|A|}P(a_t \mid a_{\lt t}, Q, R(Q,C), \phi).
$$

Latent Memory 改变了这个接口：系统不再存储并传递原始证据，而是存储一组紧凑 latent token。latent token 既作为检索表示用于选择相关证据，又作为连续证据 token 被直接提示给生成器。推理阶段完整管线包含四个组件。

**记忆压缩。** 对每条证据 $x_i\in C$，使用小型 compressor LLM/VLM $\theta$ 产生一个 Latent Memory token。具体做法是把 $x_i$ 后接一个可学习 embedding `[MEM]`，并取该 token 的最终 hidden state 作为 latent token：

$$
z_i=\theta(x_i,[MEM])\in \mathbb{R}^{d_\theta}.
$$

收集所有 latent token 得到 Latent Memory：

$$
M=\{z_i\}_{i=1}^{N}.
$$

原始证据随后可被丢弃。

图 2：compressor 与 decoder 的训练过程包含三种损失：重建损失、对比损失和蒸馏损失。重建损失让 latent token 能恢复文本或图像 embedding；对比损失把查询 embedding 与正证据 latent token 对齐；蒸馏损失对齐原始证据提示和 latent token 提示下的生成器输出。

**检索 Latent Memory。** 如果上下文数量很多，即使压缩后的 latent token 仍会带来处理压力。因此作者让 Latent Memory token 可检索。检索投影 MLP 把 $z_i$ 投影到 $d_r$ 维检索空间：

$$
\tilde{z}_i=\mathrm{MLP}_r(z_i).
$$

对查询 $q$，compressor 产生查询表示 $\tilde{q}\in\mathbb{R}^{d_r}$。然后以内积检索 top-k memory：

$$
I=\arg\operatorname{top-k}_{i}\ \tilde{q}^{\top}\tilde{z}_i.
$$

**Latent-conditioned generation。** 检索到的 latent token $\{z_i:i\in I\}$ 会被映射到 frozen LLM/VLM $\phi$ 的隐藏空间中。令 $\hat{z}_j$ 表示第 $j$ 个被检索 memory 对应的投影 latent token，使用另一个生成侧投影 $W^g\in \mathbb{R}^{d_\phi\times d_\theta}$：

$$
\hat{z}_i=W^g z_i.
$$

生成概率为：

$$
P(A \mid Q,C,\phi,\theta)=\prod_{t=1}^{|A|}
P(a_t \mid a_{\lt t}, Q, \hat{z}_1,\ldots,\hat{z}_k,\phi).
$$

**重建（可选）。** 为了保留一定可解释性，Latent Memory 可以大致重建回原始多模态上下文。对文本证据或图像 caption，微调 decoder $\pi$，自回归恢复原文本：

$$
P(x_i\mid z_i)=\prod_{t=1}^{|x_i|}P(x_{i,t}\mid x_{i,\lt t},z_i,\pi).
$$

对图像证据，论文不直接重建像素，而是训练 MLP 预测原图像的 CLIP embedding。随后可用预训练 diffusion-based image generator unCLIP，在恢复的 CLIP embedding 条件下粗略恢复图像。

### 3.2 训练 Latent Memory compressor

Latent Memory 同时承担检索、信息提供和可选重建三种角色。因此，训练需要让一个 latent token 同时支持这些角色。

训练过程优化三种互补信号：

1. 重建目标鼓励每个压缩 latent token $z_i$ 保留原证据内容。
2. 对比目标塑造检索空间，使查询只靠近其 supporting evidence。
3. 蒸馏目标让“以 latent memory 为条件的 frozen generator 行为”接近“以原始证据为条件的 frozen generator 行为”。

为避免灾难性遗忘，较大的生成器 $\phi$ 在训练期间始终 frozen。优化对象只包括 compressor LLM/VLM $\theta$ 的 LoRA、重建 decoder LLM $\pi$ 的 LoRA、检索投影 $W^r$ 和生成投影 $W^g$。训练只需要正样本监督，不需要额外答案标签等监督信号。

**多模态重建损失。** one-token memory 不应退化为纯判别式检索 ID，而应该保留可恢复的证据信息。对文本证据 $x_i$ 或图像 caption，微调 LLM decoder $\pi$，以 teacher-forcing 方式从 $\theta$ 压缩得到的 Latent Memory $z_i$ 中重建 $x_i$：

$$
L^{text}_{Recon}=-\sum_i\sum_{t=1}^{|x_i|}\log P_{\pi}(x_{i,t}\mid x_{i,\lt t},z_i).
$$

对图像证据，不重建像素，而是预测原图像 CLIP embedding $v_i$：

$$
L^{img}_{Recon}=\sum_i\lVert v_i-\mathrm{MLP}(z_i)\rVert_2^2.
$$

多模态训练时，重建项为：

$$
L_{Recon}=L^{text}_{Recon}+\lambda_{img}L^{img}_{Recon}.
$$

**对比检索损失。** 检索投影把 Latent Memory $z_i$ 映射为检索向量 $\tilde{z}_i$。为了让该空间适合证据选择，另一个 compressor LoRA 会把查询表示 $\tilde{q}$ 拉近到 supporting evidence 的 latent memory，并远离无关 memory。对每个问题 $Q$，设 $M^+$ 和 $M^-$ 分别为正 latent evidence 和采样负 latent evidence。使用多正样本 InfoNCE：

$$
L_{Contrast}=\frac{1}{|M_i^+|}\sum_{\tilde{z}_j\in M^+}
-\log
\frac{\exp(\tilde{q}^{\top}\tilde{z}_j/\tau)}
{\sum_{\tilde{z}_k\in M^+\cup M^-}\exp(\tilde{q}^{\top}\tilde{z}_k/\tau)}.
$$

因为文本和图像证据都被投影到同一检索空间，同一个损失支持混合多模态 memory 上的统一检索。

**生成蒸馏损失。** 为了让 latent token 起到与原始证据类似的作用，作者加入蒸馏目标。对每个训练样本，teacher distribution 来自 frozen generator $\phi$，输入为原始正上下文 $C^+$；teacher 生成序列为 $A^{tea}$。student 使用同一个 frozen generator $\phi$，但用投影 latent memory $\hat{z}_1,\ldots,\hat{z}_k$ 替代原始上下文。训练时沿 teacher-generated trajectory 最小化 token-level KL：

$$
L_{Distill}=\sum_{t=1}^{|A^{tea}|}
\mathrm{KL}\big(
P(\cdot\mid a^{tea}_{\lt t},Q,C^+,\phi)
\parallel
P(\cdot\mid a^{tea}_{\lt t},Q,\hat{z}_1,\ldots,\hat{z}_k,\phi)
\big).
$$

这一项教会 compressor 和生成投影产生 frozen generator 能解释为证据的 latent token。蒸馏损失把 latent retrieval 接口连接到最终 QA 目标。

**总体目标。** 训练总目标为：

$$
L=\lambda_{recon}L_{Recon}+\lambda_{contrast}L_{Contrast}+\lambda_{distill}L_{Distill}.
$$

## 4 实验

论文在两个设置中评估 Latent Memory：

- 纯文本上下文 QA；
- 多模态上下文 QA。

在主要文本设置中，生成器 $\phi$ 是 frozen Meta-Llama-3-8B-Instruct，compressor $\theta$ 是带 LoRA adapter 微调的 LLaMA-3.2-1B-Instruct。为了与基于 Mistral 的 text-only latent-context baseline 对比，作者也报告了 frozen Mistral-7B-Instruct 生成器设置。在多模态设置中，作者使用 frozen LLaVA-1.5-13B 作为生成器，并微调 LLaVA-1.5-7B LoRA adapter 作为 compressor。附录 C.6 还包含 Gemma-3-12B-Instruct 生成器和 Gemma-3-4B compressor 的多模态 QA 设置。所有设置中，重建 decoder $\pi$ 都从 LLaMA-3.2-1B-Instruct 微调得到。实验在 Nvidia H200 141GB GPU 上完成。

**数据集。** 文本设置中，Latent Memory 在 HotpotQA 训练集上训练，并在 in-domain HotpotQA 验证集以及 out-of-domain 2WikiMultihopQA、MuSiQue 上评估。附录 C.2 进一步加入 NQ、TriviaQA、Qasper、WICE 来测试更大范围迁移。多模态训练和评估使用 WebQA，验证集中分别报告 image-grounded 子集和 text-grounded 子集，但检索始终在混合 text-image candidate pool 上统一进行。附录 C.2 还考虑 SlideQA 上的多模态迁移。

**Baseline。** baseline 分两类：

- 上下文式 baseline：Full Context，以及 LLMLingua、xRAG、CLaRa 等 evidence-compression baseline。
- RAG baseline：BM25 Retrieval、Dense Retrieval、Qwen-3-Embedding、Nemo Retriever、Qwen-3-VL-Embedding 等。

所有 baseline 和 Latent Memory QA 都使用相同预训练生成器。

**指标。** 文本 QA 报告 Exact Match（EM）、Token F1、Recall@k 和平均生成器输入 token 数（#Tok）。WebQA 报告 F1、答案准确率（Acc）、Recall@k 和 #Tok。#Tok 表示任务相关的生成侧 prompt budget，包括上下文长度和查询长度，不包括固定 chat-template scaffolding；多模态设置中，它反映视觉展开后的有效 token 成本。

**当前模态覆盖限制与未来方向。** 当前设计假设证据可以分解为原子文本或图像单元，并且每个单元可以被独立压缩和检索。这个假设适合 WebQA 这类混合证据场景，因为答案常由少量事实或图像支撑。但当输入含义依赖全局结构时，该假设会变成限制。例如，复杂表格需要行列关系和 layout 信息；长视频需要时间顺序；文档页可能需要 caption、图、周围文本之间的空间关系。把这些输入压缩为孤立 latent token 可能保留局部语义，但丢失结构依赖。自然的下一步是给 Latent Memory 增加位置、layout、时间等结构轴，使检索和生成能同时利用局部证据语义与全局组织。

## 6 结论

本文提出 Latent Memory，一种新的记忆范式：它把每条证据编译成一个 latent token，通过压缩查询检索 latent memory，并把它们直接输入 frozen generator 进行 QA。在文本 QA 上，它相较 RAG baseline 达到有竞争力 EM/F1，同时只需约三分之一 token。在多模态 WebQA 上，它尤其适合 image-grounded question，并在将生成成本最多降低约 10 倍的同时，取得最强平均 F1 trade-off。Latent Memory 通过统一 latent 表示提升 Recall@k，并防止上下文超过生成器上下文窗口长度。

未来，Latent Memory 可作为当前 token-level memory 范式的高效替代，适用于需要快速响应和低存储压力的场景，例如 edge device 和其他资源密集场景。作者计划把 Latent Memory 扩展到复杂表格、复杂视频等更多模态。本文聚焦外部证据，因此没有讨论由模型自己生成的 Agentic Memory。后续工作还包括把 Latent Memory 扩展到资源受限 agent 场景，以更好支持 Agentic Memory comprehension。

## 附录 A 相关工作补充

附录把相关工作进一步分为四类：

- RAG 与 embedding retrieval：原始证据 RAG 能保留证据细节，但生成阶段 token 和视觉 token 成本高。
- Evidence compression for generation：LLMLingua、ICAE、AutoCompressor、LCC 等减少生成输入，但多数只支持文本；一些 latent-context 方法需要修改或微调生成器。
- Retrieval-compression interaction：xRAG、CLaRa 等把检索和 latent-context generation 连接起来，但仍主要是文本设置，且不完全统一多模态检索和生成。
- Latent-space modeling for LLMs：continuous hidden state 可承载推理、通信和多模态表示；Latent Memory 借鉴这一方向，但目标是降低多模态上下文 QA 的存储与生成 token 成本。

## 附录 B 实现细节

### B.1 Prompt 模板

teacher 和 student 使用相同 system-user-assistant scaffold。统一 instruction 为：

“You are a helpful assistant. Answer the question concisely (a few words or a short phrase) based on the provided context.”

差异只在 evidence representation：

- teacher 看到原始 evidence；
- student 接收每条 retrieved evidence 对应的一个 latent token，并且顺序与检索顺序一致。

文本 teacher prompt 中包含 `Context 1: retrieved fact 1` 等原始事实；文本 student prompt 中包含 `Latent context 1: [LATENT]`。多模态 teacher prompt 可能包含 image placeholder 和图像 title/caption；多模态 student prompt 同样用 `[LATENT]` 替代。

### B.2 详细 pipeline

**检索投影 MLP。** 检索头把 compressor hidden state 映射到 512 维检索空间：

$$
\mathrm{retrieval\_proj}(z)=\ell_2(\mathrm{LayerNorm}(\mathrm{Linear}(z))).
$$

在所有文本和多模态实验中，线性层把 $d_\theta$ 映射到 $d_r=512$。FAISS 存储和查询前会做 $\ell_2$ 归一化，因此内积检索等价于 cosine similarity。

**生成器投影 MLP。** 生成侧 projector 把 retrieved Latent Memory vector 转换到 frozen generator hidden dimension：

$$
\mathrm{cross\_proj}(z)=\mathrm{LayerNorm}(W_2\mathrm{GELU}(W_1 z)).
$$

文本设置中，它把 Llama-3.2-1B hidden size $d_\theta=2048$ 映射到 Meta-Llama-3-8B generator hidden size $d_\phi=4096$，中间维度为 3072。多模态 LLaVA 设置中，它把 LLaVA-7B compressor hidden size 4096 映射到 LLaVA-13B generator hidden size 5120，中间维度为 4608。

**decoder 与图像重建 MLP。** 文本重建时，projected latent token 被插入 decoding prompt，decoder $\pi$ 自回归恢复原文本证据或图像 caption。对图像证据，image embedding reconstruction head 预测 frozen CLIP CLS hidden state，而不是像素：

$$
\mathrm{img\_embed\_decode\_proj}(z)=W_2\mathrm{LayerNorm}(\mathrm{GELU}(W_1z)).
$$

**在线 QA。** 推理时，query 用 query adapter 编码并投影到归一化检索空间。FAISS 返回 top-k memory。完整 latent vector 按检索得分排序，经 cross_proj 投影后通过 `inputs_embeds` 插入 frozen generator。普通 prompt token 使用 generator embedding layer；projected latent memory 被拼接在 prompt prefix 和 suffix 之间。训练和评估期间不更新生成器权重。

**可训练组件。** 文本模型为 compress、query、decode、query_decode 使用不同 LoRA adapter。多模态模型额外使用 image_decode。encoder 侧 adapter 作用于 `q_proj`、`k_proj`、`v_proj`、`o_proj`；decoder 侧还包括 `gate_proj` 与 `up_proj`。非 LoRA 可训练组件包括 `[MEM]` token、检索 projector、生成 projector、decoder projector 和 image embedding reconstruction projector。

**蒸馏训练细节。** teacher 是以原始正证据为 prompt 的 frozen generator；student 是以 projected latent memory 为 prompt 的同一个 frozen generator。文本蒸馏中，student latent context 会随机加入 0 到 3 个 hard-negative latent memory，而 teacher prompt 保持 positive-only。KL loss 在前 16 个生成答案 token 上计算。

### B.4 时间复杂度分析

设证据池为 $C=\{x_i\}_{i=1}^{N}$，每条原始文本或视觉证据的平均 token 数为 $\bar{L}$，检索深度为 $k$，每条证据的 latent token 数为 $T$，问题长度为 $|Q|$，frozen generator hidden size 为 $d_\phi$，检索 embedding model hidden size 为 $d_e$，Latent Memory compressor hidden size 为 $d_\theta$。忽略检索/search 开销，关键项是 frozen generator prefill 长度。

Table 8 主要时间复杂度：

| 方法 | 有预编译 index / memory | 无预编译 |
|---|---|---|
| Full Context | $O((|Q|+N\bar{L})^2 d_\phi)$ | $O((|Q|+N\bar{L})^2 d_\phi)$ |
| Raw-evidence RAG | $O((|Q|+k\bar{L})^2 d_\phi)$ | $O(N\bar{L}^2 d_e+(|Q|+k\bar{L})^2 d_\phi)$ |
| Latent Memory | $O((|Q|+kT)^2 d_\phi)$ | $O(N\bar{L}^2 d_\theta+(|Q|+kT)^2 d_\phi)$ |

图 6：HotpotQA 上 Full Context 与 Latent Memory 的时间分析。Compile 表示预编译，Prefill 表示答案生成前的 prefill 过程。实验重复 30 次估计方差。

这些公式来自 Transformer prefill 复杂度：长度为 $S$ 的序列经过 frozen generator 的成本为 $O(S^2d_\phi)$。Full Context 的 $S=|Q|+N\bar{L}$；RAG 在选出 $k$ 条原始证据后为 $S=|Q|+k\bar{L}$；Latent Memory 为 $S=|Q|+kT$。

因此，相比 Full Context，Latent Memory 不把整个证据池送入生成器。相比原始证据 RAG，Latent Memory 的关键区别在于检索后生成器输入更短：RAG 仍发送 $k$ 条原始证据，而 Latent Memory 只发送 $kT$ 个 latent token。由于 $T\ll \bar{L}$ 且通常 $k\ll N$，Latent Memory 具有三者中最小的在线 generator-prefill 复杂度。

### B.5 空间复杂度分析

Table 9 报告 WebQA 上每条证据的平均存储。文本侧使用官方文本片段，图像侧使用官方 WebQA 图像文件。只统计存储的证据表示，不包含小型 metadata。

Table 9 平均单项存储：

| 证据类型 | 存储表示 | 平均存储 / item | 效果 |
|---|---|---:|---|
| Text | 官方原始文本片段 | 0.23 KB | reference |
| Text | Latent Memory token | 4.00 KB | 17.6x larger |
| Image | 官方提取图像文件 | 209 KB | reference |
| Image | Latent Memory token | 8.00 KB | 26.1x smaller |

该比较说明，存储优势主要来自图像侧。纯文本短片段通常比高维 latent vector 更小，因此 text-only Latent Memory 主要应理解为减少生成侧 token 使用，而不是减少持久语料库存储。图像侧则不同：用单个 LLaVA latent token 替代每张 WebQA 图像，可以显著减少存储，并避免生成时原始视觉 token 展开。

一个 one-token LLaVA Latent Memory 存储 4096 个 bf16 值：

$$
S_{latent/image}=2\times4096=8192\ \text{bytes}.
$$

未压缩 RGB 图像的存储为：

$$
S_{image}=3HW\ \text{bytes}.
$$

所以当 $3HW>8192$，即方形图像边长约大于 52.3 像素时，Latent Memory 更省存储。如果额外存储 512 维 fp32 检索 key，阈值也只提高到约 59x59 像素。

### C.1 Token Count Ablation

该节改变每条证据分配的 latent token 数。默认模型用一个 token；作者也评估 2、4、8 token 变体，同时保持证据单元和检索粒度不变。对证据 $x_i$，多 token 版本产生：

$$
Z_i=[z_{i,1},z_{i,2},\ldots,z_{i,T}],\quad z_{i,t}\in\mathbb{R}^{d_\theta}.
$$

检索仍然每条证据使用一个 key，通过 pooling 这些 token 得到：

$$
\bar{z}_i=\frac{1}{T}\sum_{t=1}^{T}z_{i,t},\quad
\tilde{z}_i=\mathrm{LayerNorm}(W^r\bar{z}_i).
$$

分析得到三点结论：

1. 增加 latent-token budget 会稳定提升 EM 和 F1，大 token 版本在答案质量上超过主要检索 baseline。
2. 但增加 latent token 数并不会在固定 k 下带来同等幅度的 Recall@k 提升。
3. 质量提升仍保持整体 trade-off：更大 latent budget 会增加生成器 token，但仍显著低于 Full Context，并且相比原始检索 baseline 仍有优势。

### C.2 更多 domain 的泛化

作者把同一个 HotpotQA 训练 checkpoint 直接用于四个额外文本 QA benchmark：NQ、TriviaQA、Qasper、WICE。由于这些数据集没有 retrieval label 设计，未计算 R@k。结果显示，Qwen-3-Embedding RAG 整体表现最好，但 1-token 和 8-token Latent Memory 仍展示较好效率-性能权衡。8-token Latent Memory 接近 BM25 性能，同时需要约 2.5 倍更少 token。

多模态泛化方面，作者在 SlideQA 上评估，使用相同 frozen LLaVA-1.5-13B 生成器。Latent Memory 提升检索覆盖并以更少 token 达到有竞争力 EM，但 Nemo 在 EM/F1 上仍更强。

### C.3 核心训练消融

该节消融 text-only 1B compressor 的重建与蒸馏负样本设置。主要变体包括：

- Ours-1B：完整模型，同时重建正证据和采样负证据，关闭 query reconstruction。
- w/o Constructing：完全移除 evidence reconstruction。
- w/o Constructing Negative Examples：只重建正证据，不把负证据作为重建目标。
- w/ Query Reconstruction：在默认 evidence reconstruction 上加入 query reconstruction。
- w/ Distillation Negative Augmentation：蒸馏时 student latent context 加入 0 到 3 个无关负 memory，teacher 仍只看正证据。

结论是：重建损失对生成侧质量重要；负证据重建有助于 latent 空间锚定；蒸馏负样本增强能让 student 面对检索噪声更稳。

### C.4 更强文本 compressor 消融

作者还测试更强文本 compressor。总体结论是，compressor 能力提高后，Latent Memory 的检索与生成质量可以进一步改善，但该路线的主要优势仍是把 evidence 编译成生成器可直接消费的紧凑 latent。

### C.5 迁移到相似 generator

该节讨论在一个生成器下训练的 latent token 是否能迁移到相似生成器。结果表明，直接 transfer 有一定可行性，但性能依赖生成器 hidden space 与接口兼容性。对我们后续阅读而言，这一点很关键：Latent Memory 的 token 不是纯语义向量，它还包含“某个 frozen generator 如何解释它”的接口适配。

### C.6 Gemma 多模态结果

Gemma-3-12B-Instruct 设置中，Latent Memory 仍在 WebQA 上体现低 token 成本和强 image-grounded 效果。和 LLaVA 设置类似，原始图像 prompt 的 visual token 展开让 RAG baseline 成本很高，而 latent token 绕过了这一步。

### C.7 Latent Tokens as Retrievers

该节把 latent token 更多地看作 retriever，区分“检索提升”和“压缩生成提升”。总体上，Latent Memory 的收益来自两部分：统一 latent 空间可以提升检索覆盖；即使排除 Recall@k 改善，latent token 本身仍能降低生成侧输入并保持一定答案质量。

文本案例展示 Latent Memory 可以支持多跳组合，而不是只记住单句事实。两个案例都达到 exact match generation，说明 latent token 在某些场景下可以承载跨证据组合所需的信息。

### D.3 More Multimodal QA Case Studies

更多 WebQA 案例显示，同一 Latent Memory pipeline 可以在统一 text-image 候选池中检索，并让 frozen LLaVA-1.5-13B 基于 retrieved latent token 生成答案。成功案例强调图像证据压缩后仍能保留视觉语义；挑战案例反映复杂视觉比较、细粒度计数和结构化证据仍是难点。

## 后续精读建议

如果要把本文和 MemGen 对照阅读，建议优先看三条线：

1. **接口线**：本文 latent token 是外部证据压缩后经 `cross_proj` 插入 frozen generator 的 `inputs_embeds`；MemGen 的 Weaver 也是生成 latent embedding 并插入 reasoner 的 embedding 序列。
2. **训练线**：本文用 reconstruction + contrastive + distillation，让 latent token 同时可重建、可检索、可生成；MemGen 则通过 SFT/GRPO 训练 Weaver，并用 Trigger 决定插入时机。
3. **系统线**：本文的核心卖点是减少生成器 token 与视觉 token 展开；MemGen 的系统问题则更偏向推理过程中何时生成、插入、对齐 latent memory。
